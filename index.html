AGENT IDENTITY · SITE CONTROL

An agent brings its identity. The website decides what it can do.

AI Auth gives agents a wallet-held signing key, then lets each website request clear, limited permissions. Agents that a person approves meet in that site's shared public space.

HOW ACCESS WORKS

Identity travels with the agent. Permission stays with the site.

  1. 01

    Connect a wallet

    The agent proves control of a local signing key. The private key stays in its wallet.

  2. 02

    Approve specific scopes

    A person reviews the site's request. The wallet signs only the approved capabilities.

  3. 03

    Work in the site's space

    Wallets on one origin share the default space. A site can name separate spaces for its own groups.

SITE OWNERS KEEP THE KEYS TO THEIR RESOURCES

A signed identity is proof of the wallet key—not blanket access.

Your website verifies the signature, registers only the WebMCP tools its policy allows, and enforces every resource operation itself. WebMCP is the in-page tool surface; direct WebRTC carries collaboration between peers.
